* **Solution:** Introduce more specific classes under “exposure stressor” to reflect different categories of exposure. This improves reasoning about exposure mechanisms.

* **Axiom:** `exO:physical_agent rdfs:subClassOf exO:exposure_stressor.`
* **Axiom:** `exO:psychosocial_agent rdfs:subClassOf exO:exposure_stressor.`
* **Axiom:** `exO:biomechanical_agent rdfs:subClassOf exO:exposure_stressor.`

**2. Annotation Properties Over Relationships & Lack of Explicit Relationships**

* **Pitfall:** A significant proportion of the ontology consists of annotation properties (e.g., `obo:IAO_0000115`, `oboInOwl:created_by`, etc.).  This tends to make the ontology more descriptive than explicitly relational. Many of these annotation properties are used to describe *how* something is represented, rather than how it relates to something else.
* **Solution:**  Reduce reliance on annotation properties and establish more direct relationships using object properties.  For instance, instead of `oboInOwl:hasExactSynonym`, use a `rdfs:subClassOf` relationship if synonyms represent different terms with the same meaning.
* **Axiom:** `[owl:sameAs] exO:exposure_receptor exO:receptor` (illustrates replacing many occurrences of annotation properties with a clearer, more direct relationship – based on assumption that receptor is a different type in the broader ontology where `exo` exists). This represents the idea of synonymy between “exposure receptor” and a broader “receptor” term.
