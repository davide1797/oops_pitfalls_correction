**Pitfall**: `hasAttribute` is declared but not restricted (e.g., `Crushing` might have "temperature" as an attribute, but `Fermentation` would need "duration").
**Solution**:
- Define **attribute constraints** per operation type:
  ```turtle
  :BiochemicalOperation rdfs:subClassOf [
      rdf:type owl:Restriction ;
      owl:onProperty :hasAttribute ;
      owl:someValuesFrom :Duration
  ] .
  :Crushing rdfs:subClassOf [
      rdf:type owl:Restriction ;
      owl:onProperty :hasAttribute ;
      owl:someValuesFrom :Pressure
  ] .
  ```

### **19. Missing "Operation" Preconditions**
**Pitfall**: No axioms enforce **preconditions** (e.g., `Crushing` requires `Grappe` or `Berry`).
**Solution**:
- Add **input constraints**:
  ```turtle
  :Crushing rdfs:subClassOf [
      rdf:type owl:Restriction ;
      owl:onProperty :hasInput ;
      owl:someValuesFrom :Grappe , :Berry
  ] .
  ```

---
### **20. Incomplete "Product" Lifecycle**
**Pitfall**: No axioms link **byproducts** (e.g., `Stem`) back to operations (e.g., `Destemming`).
**Solution**:
- Add **output constraints**:
  ```turtle
  :Destemming rdfs:subClassOf [
      rdf:type owl:Restriction ;
      owl:onProperty :hasOutput ;
      owl:someValuesFrom :Stem
  ] .
  ```

---
### **Summary of Key Fixes**:
1. **Disjointness** for overlapping classes (e.g., `Operation` vs. `Product`).
2. **Cardinality/value restrictions** for inputs/outputs.
3. **Hierarchy corrections** (e.g., `Must-AF` as subclass of `Must`).
4. **Input/output constraints** per operation (e.g., `Crushing` → `Grappe`/`Berry`).
5. **Service product categorization** (mandatory vs. optional).
6. **Temporal/logical chaining** (e.g., `hasInput` implies `isOutputOf`).
